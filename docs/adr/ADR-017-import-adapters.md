# ADR-017: Import adapters, uploads and Agent 1 reconciliation (M6)

**Status:** Accepted (M6)

## Decision
1. **Import adapters read files, they never run tools.** CMDB (CSV/JSON), Prowler JSON, Greenbone/OpenVAS XML, OpenSCAP XCCDF, Wazuh JSON, Nmap XML and ZAP JSON arrive as operator uploads (`POST /api/v1/imports`, `import:create`: operator and connector-admin). Size <= 5 MB, UTF-8 text, **secrets redacted before hashing/storage**, stored content-addressed per tenant, metadata in an immutable `imports` table under RLS. Adapters receive only an opaque `import_id` and read it through a gateway-built reader that re-checks tenant, project, **kind** and hash on every read.
2. **Parsing is hostile-input safe.** XML via `defusedxml` with DTDs, entities and external references forbidden. The single exception is a bare `<!DOCTYPE name>` with no internal subset and no external id, which declares nothing; Nmap writes one into every XML report, so refusing it rejected all real Nmap output (found in the first live run, 2026-10-18). A second DOCTYPE, an internal subset or an external id is still refused; JSON via the stdlib parser (depth failures fail closed); CSV with field/row caps; 20,000-record cap; unknown shapes fail with `UNSUPPORTED_FORMAT`. A failed import produces **no assets**, never a partial guess.
3. **Scope applies to file contents.** For `cidr`/`host` targets every record is checked against the **signed** scope and out-of-scope records are dropped, counted (`OUT_OF_SCOPE_RECORDS_DROPPED`) and never retained in evidence. Prowler keeps only the approved account. For `asset_group` targets membership is advisory (the inventory's expected set): unknown hosts are kept as separate LOW-confidence assets and named `UNEXPECTED_ASSET`, not trusted.
4. **Profile compliance is read from the artifact.** An Nmap report whose recorded command line leaves the approved bounded profile (scripts, -sV/-A/-O, -T4+, >100 ports, >2 retries, `-iL`, ...) is refused. A ZAP import under the baseline profile that contains active-scan rule ids (40000-49999) is refused; the ZAP **active** profile is class ACTIVE and needs explicit approver acknowledgement.
5. **Agent 1 (deterministic).** CMDB reconciliation: placeholder owners/criticality stay UNKNOWN, duplicates are flagged and both kept, same-id/different-identity records are conflicts and are not ingested, stale records are named. Scanner hosts are mapped onto canonical assets only when unambiguous (ip+hostname agree = HIGH; one signal = MEDIUM); conflicting or multiple candidates are `AMBIGUOUS_IDENTITY` and become a separate asset. **HIGH/MEDIUM confidence is reserved for members of the authoritative inventory**; scanners agreeing with each other never promote an unknown host (found by a test).
6. **Coverage honesty.** One ledger per target **and adapter**; gap warnings (`PERMISSION_DENIED`, `AGENT_DISCONNECTED`, `SCAN_INCOMPLETE`, `RULES_NOT_CHECKED`, `FEED_STALE`, `OWNER_UNKNOWN`, `STALE_RECORD`, `DUPLICATE_CANDIDATE`, ...) are copied into the ledger reasons; a disconnected agent or down host is UNREACHABLE, a TestResult with no evaluated rules is UNSUPPORTED (never "no failures"); a report with no assets is the existing `ZERO_ASSETS_RETURNED` anomaly. Observations are only emitted where the evidence supports a statement.
7. **Registry hardening.** Registration refuses mutating adapters, bad ids/versions/profiles/target kinds, parameter models that accept unknown fields, import adapters without declared kinds/formats or an `import_id` parameter, and live adapters declaring import kinds. `health()` reports HEALTHY/DEGRADED/DISABLED; `/connectors` exposes kind, import kinds, formats and health. A contract test is parametrised over every adapter.
8. **Policy pack `import-baseline:1.0.0`** (13 controls, rules apply by `asset_class`) and a new `disjoint` operator for list-valued observations (risky open ports).

## Known limitations
- **Raw uploads keep the operator's original file** (redacted for secret patterns only), including records outside the scope. No API returns them; adapters read them; retention/purge is not enforced yet (M8). Pre-filter exports where possible.
- Formats follow the documented structures but were built against **synthetic** fixtures; behaviour on real Prowler/Greenbone/Wazuh/OpenSCAP/Nmap/ZAP versions is **unverified**. The Wazuh input is a documented-structure combination of its agents and SCA API responses, not a native single export.
- ~~No task dependency ordering~~ **Resolved (migration 0019):** inventory imports (CMDB, NetBox, ServiceNow) are queued first and every other task in the run lists them in `depends_on`; the worker does not claim a task while a dependency is queued or running. If an inventory task fails, the dependent tasks still collect evidence and carry `INVENTORY_DEPENDENCY_<STATUS>:<task>`, and no scanned host is promoted to a known asset.
- ~~No upload or import-parameter UI~~ **Resolved:** the launch review step shows one picker per import adapter (choose an earlier upload or upload a new file of an accepted kind); launch stays disabled until every import adapter has a file. Upload rejections (size, binary content, kind) are shown with their reason code.
- Asset-group membership is advisory (point 3); a group scope cannot prove a host is "in" the approved estate beyond the inventory's expected list.
- No live Nmap/ZAP/Greenbone execution exists (those are M9/never in the MVP).
